# Авторизация и аренды

Установите обновлённые зависимости.

    python -m pip install -r requirements.txt

Запустите приложение, зарегистрируйтесь на главной странице и войдите.
Регистрация создаёт аккаунт USER и связанную карточку клиента в одной транзакции.
Существующие клиенты автоматически к новым аккаунтам не привязываются.

Чтобы назначить администратора, выполните на сервере после регистрации аккаунта.

    python create_admin.py ваш_логин

Назначать роль через форму регистрации нельзя. Роли проверяются по базе при каждом запросе.

## Доступ

- Каталог доступен всем.
- USER видит свои аренды и создаёт брони на себя. Переданный чужой client_id заменяется собственным.
- ADMIN видит общий журнал, оформляет аренду, выдаёт оборудование по брони и принимает возврат.
- Управление оборудованием и доступ к клиентам и сотрудникам требуют ADMIN.
- Чужая отдельная аренда возвращает 404. Отсутствующий или истёкший JWT возвращает 401, недостающая роль — 403.

## API

POST /auth/registration принимает JSON с username, password, full_name, phone.
POST /auth/login принимает JSON с username и password, возвращает access_token на 30 минут.
GET /auth/me возвращает профиль текущего аккаунта.

Токен передаётся в заголовке Authorization со значением Bearer и токеном через пробел.
В Swagger нажмите Authorize и введите токен. В интерфейсе токен хранится в sessionStorage
на время вкладки. Выход удаляет его из вкладки. Выданный токен действует до истечения срока.

GET /rentals/ поддерживает status_filter (ACTIVE, RESERVED, RETURNED), date_from и date_to.
Период фильтруется по пересечению дат, границы включаются.
GET /rentals/{id} проверяет владельца.
POST /rentals/ оформляет выдачу администратором.
POST /rentals/book создаёт бронь.
POST /rentals/{id}/issue выдаёт бронь в период её действия.
POST /rentals/{id}/return принимает возврат.
Повторная выдача активной аренды и повторный возврат возвращают текущее состояние.

Брони и активные аренды блокируют пересекающиеся даты. Оборудование в ремонте не выдаётся
и не бронируется. Проверка и запись сериализуются SQLite-транзакцией BEGIN IMMEDIATE.

## Секрет и данные

При первом входе создаётся локальный файл .jwt-secret. Он исключён из Git.
Можно задать JWT_SECRET через окружение. Все процессы сервера должны использовать один секрет.
Смена секрета делает старые токены недействительными.
Новая таблица auth_users создаётся при запуске. Существующие таблицы и аренды сохраняются.

## Проверка

    python -m pip install httpx
    python tests/check_rental_auth.py

Проверка работает с временной базой и проверяет JWT, роли, чужие записи,
одновременные брони, фильтры, выдачу и возврат.
