# 🤝 Правила работы для 4-х пар (CONTRIBUTING)

В проекте работают 8 человек (4 пары по 2 человека). Чтобы не мешать друг другу и не ломать код, мы соблюдаем эти простые правила.

---

## 👥 Распределение зон ответственности

| Пара | Ветка | Основные файлы | Задачи |
|---|---|---|---|
| **Пара 1** | `feature/equipment` | `routers/equipment.py` | Доделать PUT, DELETE, фильтрацию по статусу |
| **Пара 2** | `feature/clients` | `routers/clients.py` | Реализовать GET, POST, поиск по телефону |
| **Пара 3** | `feature/rentals` | `routers/rentals.py`, `services.py` | Бронирование, проверка пересечения дат, возврат |
| **Пара 4** | `feature/frontend` | `templates/`, `static/` | Формы, списки, кнопки аренды, верстка |
| **Сотрудники** | `feature/employers` | `routers/employers.py` | Учет менеджеров, роли, авторизация |

> ⚠️ **Главное правило:** НЕ меняйте файлы других пар без предварительного согласования в общем чате!

---

## 🌿 Как работать в паре (Команды Git)

### 1. Перед началом работы:
Всегда скачивайте свежие изменения из своей ветки:
```bash
git checkout feature/<ваша-ветка>
git pull origin feature/<ваша-ветка>
```

### 2. Сохранение написанного кода:
Делайте коммиты часто, с понятным описанием на русском языке:
```bash
git add .
git commit -m "feat: добавлена проверка дубликата номера телефона"
git push origin feature/<ваша-ветка>
```

### 3. Открытие Pull Request (PR):
Когда задача выполнена и проверена в `/docs`:
1. Зайдите на GitHub в репозиторий.
2. Нажмите **Compare & pull request**.
3. **ВАЖНО:** Выберите базовую ветку **`base: develop`** (не `main`!).
4. Напишите капитану, что задача готова к ревью.
